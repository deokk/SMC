# 모델 설계도

이 문서는 따릉이 자전거 수 예측 모델의 학습과 실제 예측 애플리케이션의 설계 내용을 기술합니다.

---
## 1. 모델 학습 스크립트 (`xgboost_model_trainer.py`)

### 1.1. 목적
- 광진구의 2024년 따릉이 사용 기록(`gwangjin_2024_data.csv`)을 사용하여, 특정 시점의 자전거 수를 기반으로 미래 6시간 동안의 시간대별 자전거 수를 예측하는 머신러닝 모델을 학습시키고 저장합니다.

### 1.2. 주요 실행 흐름
스크립트는 다음 3단계의 프로세스를 순차적으로 실행합니다.

#### 1.2.1. 데이터 로딩 및 전처리 (`load_data` 함수)
1.  **데이터 로딩**: `gwangjin_2024_data.csv` 파일을 로드합니다.
2.  **타임스탬프 생성**: 날짜와 시간 컬럼을 조합하여 `timestamp`를 생성합니다.
3.  **중복 데이터 처리**: 동일한 대여소, 동일한 시간에 중복된 데이터가 있을 경우, 자전거 수의 평균을 내어 데이터를 정규화합니다.
4.  **시계열 데이터 재구성**: 모든 대여소에 대해 2024년 전체 기간 동안 시간 단위로 끊김 없는 `(대여소 ID, 타임스탬프)` 인덱스를 생성합니다.
5.  **결측치 처리**: 재구성 과정에서 생긴 빈 데이터(자전거 수)는 `interpolate` (선형 보간)을 사용하여 채우고, 남은 결측치는 0으로 채웁니다.

#### 1.2.2. 피처 엔지니어링 (`create_features` 함수)
- 모델의 예측 성능을 높이기 위해 기존 데이터로부터 새로운 변수(Feature)를 생성합니다.
1.  **시간 관련 변수**:
    - **주기성 변수**: 시간(0-23시)과 요일(0-6)을 sin, cos 함수를 이용해 주기적 특성을 갖는 변수(`hour_sin`, `hour_cos` 등)로 변환합니다. 이는 23시와 0시가 가깝다는 관계를 모델이 학습할 수 있게 합니다.
    - **일반 시간 변수**: 연중 일자(`day_of_year`), 월(`month`) 등의 정보도 변수로 추가합니다.
2.  **지연 변수 (Lag Features)**:
    - 과거의 데이터는 미래 예측에 중요한 정보입니다. 현재 시점으로부터 1, 2, 3, 24, 168시간 전의 자전거 수(`bike_count_lag_1h` 등)를 변수로 추가합니다.
3.  **이동 평균 변수 (Rolling Window Features)**:
    - 데이터의 단기적인 추세를 파악하기 위해, 최근 3시간 및 24시간 동안의 자전거 수 평균(`bike_count_rolling_mean_3h` 등)을 변수로 추가합니다.

#### 1.2.3. 모델 학습 및 저장 (`train_model` 함수)
1.  **모델 정의**:
    - **모델 종류**: `XGBoost Regressor`를 사용합니다. 이는 성능이 뛰어나고 대용량 데이터 처리에 유리한 부스팅 기반의 모델입니다.
    - **다중 출력**: `sklearn.multioutput.MultiOutputRegressor`로 XGBoost 모델을 감싸, 한 번의 예측으로 미래 1시간부터 6시간까지 총 6개의 값을 동시에 예측할 수 있도록 구성합니다.
2.  **데이터 분리**: 전체 데이터 중 과거 80%를 학습용(Train Set)으로, 최근 20%를 모델 성능 검증용(Test Set)으로 분리합니다.
3.  **학습 및 평가**: 학습용 데이터로 모델을 학습시키고, 검증용 데이터로 예측을 수행하여 MAE, RMSE 같은 지표로 모델의 성능을 평가합니다.
4.  **모델 저장**: 학습이 완료된 모델은 `xgboost_multioutput_model.joblib` 파일로, 학습에 사용된 변수 목록은 `feature_columns.joblib` 파일로 저장하여 예측 시에 재사용할 수 있도록 합니다.

## 2. 예측 애플리케이션 (`prediction_app.py`)

### 2.1. 목적
- `xgboost_model_trainer.py`에서 학습된 모델을 사용하여, 사용자가 원하는 시점의 모든 광진구 대여소의 자전거 수를 예측하는 기능을 제공합니다.

### 2.2. 핵심 구성요소: `BikePredictor` 클래스
- 예측에 필요한 모든 데이터와 모델을 미리 로드하고, 예측 요청을 처리하는 클래스입니다.

#### 2.2.1. 초기화 (`__init__` 메소드)
- `BikePredictor` 클래스가 생성될 때 한 번만 실행되며, 다음 작업을 수행하여 예측 준비를 마칩니다.
1.  **모델 및 변수 로드**: `xgboost_multioutput_model.joblib`과 `feature_columns.joblib`를 로드합니다.
2.  **과거 데이터 및 피처 준비**: `xgboost_model_trainer.py`와 동일한 로직으로 `gwangjin_2024_data.csv`를 읽고 모든 피처를 계산합니다. 이 결과(`df_features`)를 클래스 내에 저장해두어, 예측 요청 시마다 피처를 다시 계산할 필요 없이 빠르게 조회할 수 있도록 합니다.

### 2.3. 예측 로직
- 예측은 다음 두 단계의 함수 호출로 이루어집니다.

#### 2.3.1. `predict_all_stations` (모든 대여소 예측)
1.  사용자로부터 예측을 원하는 미래 시점(`n_minutes`)을 입력받습니다.
2.  광진구의 모든 대여소 ID를 순회하며 각 대여소에 대해 다음을 호출합니다.
    - `get_real_time_bike_count_from_file`: 각 대여소의 현재 자전거 수를 가져옵니다.
    - `predict`: 현재 자전거 수와 과거 데이터를 기반으로 미래 자전거 수를 예측합니다.
3.  모든 대여소의 예측 결과를 `{대여소ID: 예측된_자전거수}` 형태의 딕셔너리로 취합하여 반환합니다.

#### 2.3.2. `predict` (단일 대여소 예측)
1.  **입력**: `station_id`, `n_minutes`(예측할 미래 시점), `real_time_bike_count`(현재 자전거 수)
2.  **과거 피처 조회**: 초기화 시 미리 계산해 둔 `df_features`에서 해당 `station_id`의 가장 최근 피처 벡터(과거 데이터 기반)를 가져옵니다.
3.  **모델 예측**: 조회된 피처 벡터를 모델에 입력하여 미래 6시간의 시간대별 자전거 수를 예측합니다.
4.  **최종 예측값 보간**:
    - 예측의 기준점(t=0)은 `real_time_bike_count` (실시간 자전거 수)로 설정합니다.
    - 모델이 예측한 1시간 후 자전거 수와 현재 자전거 수 사이를 선형 보간(Linear Interpolation)하여, 사용자가 요청한 `n_minutes` 시점의 최종 예측값을 계산합니다.
    - 이를 통해 실시간 현황을 반영한 더 정확하고 유연한 분 단위 예측이 가능해집니다.

### 2.4. 실시간 데이터 연동 (`get_real_time_bike_count_from_file` 함수)
- 서버로부터 실시간 자전거 수 정보를 가져오는 부분을 시뮬레이션합니다.
- `bike_data.txt` 파일을 읽어 JSON 형식의 데이터를 파싱합니다.
- 예측하려는 대여소 ID와 일치하는 정보를 파일에서 찾아 `available_bikes` 값을 반환합니다.
- 만약 파일에 정보가 없거나 파일을 읽는 데 실패할 경우, 임의의 숫자를 반환하여 시스템이 중단되지 않도록 합니다.
