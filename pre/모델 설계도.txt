# 모델 설계도 (v2.0)

이 문서는 서울시 공공자전거 '따릉이'의 수요 예측 시스템에 대한 전체적인 설계와 사용 방법을 기술합니다. 시스템은 단기(0-6시간) 및 장기(6시간-4일) 예측을 모두 처리할 수 있는 하이브리드 모델을 기반으로 하며, 실시간 API 서버를 통해 예측 결과를 제공합니다.

---
## 1. 프로젝트 개요

광진구 내 따릉이 정류소들의 미래 자전거 수를 예측하는 것을 목표로 합니다. 이를 위해 두 종류의 예측 모델(XGBoost, LSTM)을 조합하여 사용하며, 사용자는 독립적인 예측 스크립트 또는 실시간 API 서버를 통해 예측 결과를 얻을 수 있습니다.

---
## 2. 디렉토리 구조

-   `gwangjin_2024_data.csv`: 모델 학습에 사용되는 2024년 광진구 따릉이 운행 데이터.
-   `station_information.csv`: 정류소 ID와 이름 등 기본 정보.
-   `bike_data.txt`: 실시간 자전거 현황을 시뮬레이션하는 JSON 데이터.
-   `xgboost_model_trainer.py`: 단기 예측(XGBoost) 모델과 기준 예측(Baseline) 데이터를 생성하는 스크립트.
-   `lstm_model_trainer.py`: 장기 예측(LSTM) 모델을 학습시키는 스크립트.
-   `prediction_app.py`: 명령줄(CLI) 기반의 통합 예측 애플리케이션.
-   `app.py`: FastAPI를 사용한 실시간 예측 API 서버.
-   `xgboost_multioutput_model.joblib`: 학습된 XGBoost 모델 파일.
-   `lstm_model.h5`: 학습된 LSTM 모델 파일.
-   `scaler.pkl`: LSTM 모델의 데이터 정규화/복원을 위한 스케일러.
-   `baseline_predictions.json`: XGBoost 모델이 생성한 요일/시간별 기준 예측값.
-   `모델 설계도.txt`: 본 문서.

---
## 3. 데이터 흐름 및 처리

1.  **과거 데이터 (`gwangjin_2024_data.csv`)**:
    - 모델 학습의 근간이 되는 데이터입니다.
    - 모든 정류소에 대해 시간별로 누락된 데이터가 없도록 전처리(보간) 과정을 거칩니다.
    - 시간, 요일, 공휴일 등 시간 관련 특성과 과거 자전거 수(Lag), 이동 평균 등 통계적 특성을 피처(Feature)로 생성하여 모델 학습에 사용합니다.

2.  **실시간 데이터 (`bike_data.txt`)**:
    - API 서버(`app.py`)와 예측 스크립트(`prediction_app.py`)에서 현재 시점의 자전거 수를 가져오기 위해 사용됩니다.
    - 실제 운영 환경에서는 서울시 열린데이터광장 API 등을 통해 얻는 데이터를 시뮬레이션합니다.

---
## 4. 모델 학습 (`***_trainer.py`)

### 4.1. 단기 예측 모델 학습 (`xgboost_model_trainer.py`)

-   **목적**: 2가지 결과물을 생성합니다.
    1.  **단기 예측 모델**: 특정 시점의 데이터를 기반으로 미래 6시간의 자전거 수를 예측하는 `XGBoost` 모델을 학습하여 `xgboost_multioutput_model.joblib`으로 저장합니다.
    2.  **기준 예측 데이터**: 모든 정류소에 대해 모든 요일/시간대(총 7*24=168개 슬롯)별로 6시간 예측값을 미리 계산하여 `baseline_predictions.json`으로 저장합니다. 이는 `app.py`의 `v3` 예측 로직에 사용됩니다.
-   **실행**: `python xgboost_model_trainer.py` 명령으로 실행합니다.

### 4.2. 장기 예측 모델 학습 (`lstm_model_trainer.py`)

-   **목적**: 과거 7일(168시간)의 시계열 데이터를 기반으로 미래 4일(96시간)의 자전거 수를 예측하는 `LSTM` 모델을 학습합니다.
-   **모델 아키텍처**:
    - `LSTM` 레이어를 사용하여 시계열 데이터의 장기 의존성을 학습합니다.
    - 정류소별로 데이터 분포가 다르므로, `MinMaxScaler`를 정류소마다 별도로 적용하고, 이 스케일러들을 `scaler.pkl`에 저장하여 예측 시 사용합니다.
-   **결과물**:
    - `AI/models/lstm_model.h5`: 학습된 LSTM 모델.
    - `AI/models/scaler.pkl`: 정류소별 스케일러 딕셔너리.
-   **실행**: `python lstm_model_trainer.py` 명령으로 실행합니다.

---
## 5. 예측 시스템

### 5.1. 명령줄 기반 예측 (`prediction_app.py`)

-   **목적**: 사용자가 터미널에서 직접 원하는 시간을 입력하여 광진구 전체의 자전거 수를 예측합니다.
-   **핵심 컴포넌트 (`HybridPredictor`)**:
    - `XGBoostPredictor`와 `LSTMPredictor`를 내부적으로 관리합니다.
    - 예측 시간(`n_minutes`)에 따라 적절한 모델을 선택하여 예측을 수행하는 '오케스트레이터' 역할을 합니다.
        - **0 ~ 6시간 (360분) 예측**: `XGBoostPredictor` (단기 모델) 호출.
        - **6시간 ~ 4일 (5760분) 예측**: `LSTMPredictor` (장기 모델) 호출.
-   **실행 방법**:
    - `python prediction_app.py <분>` 형식으로 실행합니다.
    - 예시: `python prediction_app.py 720` (12시간 후의 광진구 전체 자전거 수 예측)
    - 명령줄 인자가 없으면 단일 정류소에 대한 데모 예측을 수행합니다.

### 5.2. 실시간 API 서버 (`app.py`)

-   **목적**: FastAPI를 이용하여 실시간으로 따릉이 관련 데이터를 조회하고 예측 결과를 받을 수 있는 API 엔드포인트를 제공합니다.
-   **실행 방법**: `uvicorn app:app --reload` 명령으로 서버를 실행합니다.
-   **주요 엔드포인트**:
    -   `GET /stations/realtime`: `bike_data.txt`를 읽어 광진구 모든 정류소의 현재 자전거 수를 JSON 형식으로 반환합니다.
    -   `GET /predict/v2/ddareungi`:
        - `station_id`와 `n_minutes`를 입력받아 단일 정류소를 예측합니다.
        - `prediction_app.py`와 유사한 하이브리드 로직을 사용하지만, 실시간 자전거 수를 `realtime` 엔드포인트에서 직접 가져와 사용합니다.
    -   `GET /predict/v3/ddareungi`:
        - **가장 발전된 예측 로직**을 사용합니다.
        - `baseline_predictions.json`에서 현재 요일/시간에 가장 가까운 **기준 예측값**을 가져옵니다.
        - `realtime` 엔드포인트에서 얻은 **실제 현재값**과 기준 예측값의 **차이(편차)**를 계산합니다.
        - 이 편차를 미래 기준 예측값에 더하여 최종 예측 결과를 보정합니다. (Prediction = Baseline + Deviation)
        - 이 방식은 실시간 현황을 매우 빠르고 효율적으로 예측에 반영할 수 있는 장점이 있습니다.

## 6. 전체 시스템 사용 순서

1.  **모델 학습 (최초 1회 또는 주기적 실행)**:
    - `python xgboost_model_trainer.py` 실행.
    - `python lstm_model_trainer.py` 실행.

2.  **예측 수행 (선택)**:
    - **옵션 A: 간편한 통합 예측**: 터미널에서 `python prediction_app.py <분>`을 실행하여 특정 시간 후의 광진구 전체 자전거 수를 확인합니다.
    - **옵션 B: 실시간 서버 연동 예측**:
        1. `uvicorn app:app --reload`로 API 서버를 실행합니다.
        2. 웹 브라우저나 API 클라이언트(Postman 등)로 원하는 엔드포인트에 접속하여 실시간 데이터 조회 및 예측을 수행합니다.
           - `http://127.0.0.1:8000/predict/v3/ddareungi?station_id=3501&n_minutes=30`
